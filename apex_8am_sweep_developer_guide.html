What this means

On Tradovate, the moment your account peaks at $50,800 intraday — even on an open trade you haven't closed — your drawdown floor permanently moves to $48,800. If that trade then reverses and closes at $50,400, you've spent $800 of your $2,000 drawdown buffer for a $400 gain. The floor does not come back down.

Why it favours the steady approach

Small, closed targets (40–80pts) keep unrealized excursions tight. The floor moves predictably with closed P&L. Large runners (150pt targets) spike the unrealized peak, ratchet up the floor, then leave almost no cushion if the trade partially retraces. The steady approach preserves your $2,000 buffer across the full eval period.

The 8am Sweep Setup — Overnight High / Low Liquidity Grab

Visual — Classic ONH Sweep & Reversal (Bearish Example)
What it does

Around 8am ET, institutional algorithms probe above the Overnight High or below the Overnight Low to trigger resting stop orders. The resulting wick is the sweep. When price closes back inside the overnight range, those stops have been hunted and the move reverses. The Pine script identifies this wick-close pattern on the 1m or 3m chart.

Why it matters for the eval

The sweep is a time-boxed event (7:55–8:30am window). There is no ambiguity about whether a setup exists — it either fires in that window or the session is skipped entirely. This hard time gate protects the DLL ($1,000/day) by eliminating random midday trades that don't have an identifiable edge.

Pine Script Implementation — ONH/ONL & Sweep Detection

Pine Script — Strategy Declaration & Inputs
// @S3 Development | Project Black-Box
// Apex 8am Sweep Strategy — MNQ EOD 50k Eval
//@version=6
strategy("Apex 8am Sweep — MNQ", overlay=true,
  initial_capital=50000, default_qty_type=strategy.fixed,
  default_qty_value=2, currency=currency.USD)

// ── Session & Window ──────────────────────────────────────────
sweep_open   = input.session("0755-0830", "Sweep Window (ET)")
show_levels  = input.bool(true,  "Show ONH/ONL Lines")

// ── Sweep Detection ───────────────────────────────────────────
vol_mult     = input.float(1.5,  "Volume Filter Multiplier", minval=1.0)
sweep_buffer = input.int(5,    "Sweep Buffer (pts above/below ONH/ONL)")

// ── Risk Management ───────────────────────────────────────────
stop_buffer  = input.int(8,    "Stop Buffer Beyond Sweep Wick (pts)")
target_pts   = input.int(80,   "Full Target (pts) — Steady Mode")
scale_pct    = input.float(0.5,  "Scale-Out at % of Target")
daily_loss   = input.int(500,  "GCP Daily Loss Limit ($)")
Pine Script — Overnight High/Low Detection
// Overnight session = 6pm ET prior day to 9:30am ET (RTH open)
overnight_session = "1800-0930"

var float onh = na   // Overnight High
var float onl = na   // Overnight Low

in_overnight = not na(time(timeframe.period, overnight_session))

// Reset ONH/ONL each day at 6pm ET
new_overnight = ta.change(dayofweek) or (hour == 18 and minute == 0)
if new_overnight
    onh := na
    onl := na

// Track ONH and ONL throughout overnight session
if in_overnight
    onh := na(onh) ? high : math.max(onh, high)
    onl := na(onl) ? low  : math.min(onl, low)

// Plot on chart
plot(show_levels ? onh : na, "ONH", color.new(color.red,   30), linewidth=2, style=plot.style_linebr)
plot(show_levels ? onl : na, "ONL", color.new(color.green, 30), linewidth=2, style=plot.style_linebr)
What it does

Tracks the rolling high and low of the overnight session (6pm–9:30am ET) using var float persistent variables that reset each day. The levels are plotted as dashed horizontal lines on the chart, visible in the 7:55–8:30am window when the sweep typically occurs.

Why it matters

The ONH and ONL are the precise price levels where stop-loss clusters from overnight traders accumulate. Algorithms sweep these levels to grab that liquidity. Without accurately tracking these levels per session, the sweep detection has no reference point to measure against.

Sweep Detection & Volume Filter

Pine Script — Sweep Candle Identification
// Are we inside the sweep window?
in_window = not na(time(timeframe.period, sweep_open))

// Average volume over last 20 bars for comparison
avg_vol = ta.sma(volume, 20)

// Volume filter: sweep candle must have above-average volume
vol_ok = volume > avg_vol * vol_mult

// ONH Sweep: wick pierces above ONH, candle closes BACK INSIDE range
// — wick above, body below: the classic liquidity grab pattern
bear_sweep = in_window
           and not na(onh)
           and high > onh + sweep_buffer  // Wick cleared ONH
           and close < onh               // Candle closed back inside
           and close < open              // Bearish close
           and vol_ok                     // Volume confirms conviction

// ONL Sweep: wick pierces below ONL, candle closes BACK INSIDE range
bull_sweep = in_window
           and not na(onl)
           and low < onl - sweep_buffer   // Wick cleared ONL
           and close > onl               // Candle closed back inside
           and close > open              // Bullish close
           and vol_ok                     // Volume confirms conviction

// Highlight sweep candles on chart
bgcolor(bear_sweep ? color.new(color.red,   80) : na)
bgcolor(bull_sweep ? color.new(color.green, 80) : na)

The Volume Filter — Why It's Critical

A wick that sweeps ONH on thin volume is a trap signal, not a real sweep. Institutional liquidity grabs leave a volume signature: the sweep candle spikes volume as stops are triggered. Set vol_mult to 1.5× average as a baseline. For MNQ, calibrate to your chart timeframe:

1m chart vol_mult = 2.0–2.5   3m chart vol_mult = 1.5–2.0   5m chart vol_mult = 1.2–1.5

The "and" chain

Every condition in bear_sweep must be simultaneously true. The time window gate (in_window) prevents any signal firing outside 7:55–8:30am. The volume gate eliminates low-conviction wicks. All five conditions together produce a high-specificity signal with very few false positives.

Why close matters more than wick

The close back inside the range is the confirmation that the sweep completed. A candle that wicked above ONH and closed above ONH is a breakout, not a sweep. The close condition is what distinguishes a liquidity grab from a trend continuation.

GCP Python — NIGHTHAWK Validation Gate (Pseudocode)
def validate_signal(payload, account_state):
    # 1. Auth check
    if payload["secret"] != SECRET_TOKEN:
        return reject("401 — bad secret")

    # 2. Model routing
    if payload["model_id"] != "APEX-8AM-SWEEP-V1":
        return reject("404 — unknown model")

    # 3. Time window gate (ET) — no trades outside sweep window
    et_now = datetime_et()
    if not (time(7,55) <= et_now <= time(8,30)):
        return reject("OUTSIDE SWEEP WINDOW — signal ignored")

    # 4. Daily loss limit gate
    if account_state["daily_pnl"] <= -DAILY_LOSS_LIMIT:
        return reject("DLL HIT — trading paused for session")

    # 5. Position gate — no pyramiding
    if account_state["open_positions"] > 0:
        return reject("POSITION OPEN — max 1 trade at a time")

    return approve(payload)
What it does

The GCP middleware runs five sequential checks before any order reaches Tradovate. The time window check (#3) is the most important for the eval — it enforces the 7:55–8:30am gate at the infrastructure level, independent of the Pine Script logic. Double-gating prevents any edge-case order that slips through late.

The DLL gate is your eval insurance

If a bad sweep trade hits the GCP-configured daily loss limit ($500 recommended, well within Apex's $1,000 DLL), the middleware blocks all further orders for the rest of the session. The account stays alive. Next day, the GCP daily P&L counter resets automatically at 6pm ET.

Exit Logic — Scale-Out & Breakeven Trail

Pine Script — Scale Out at 50% Target + BE Trail
// Scale out half position at 50% of target
scale_target = target_pts * scale_pct   // Default: 40pts

strategy.exit("SCALE_LONG", "SWEEP_LONG",
    qty_percent = 50,                   // Close half the position
    profit      = scale_target * 4,     // In ticks (4 ticks per point)
    comment     = "SCALE_OUT_50")

// Once scaled, trail remaining 50% to full target with BE stop
// Move stop to breakeven after scale-out fires
be_triggered = strategy.closedtrades > 0 and
               strategy.closedtrades.exit_comment(strategy.closedtrades - 1) == "SCALE_OUT_50"

if be_triggered and strategy.position_size > 0
    strategy.exit("RUNNER_LONG", "SWEEP_LONG",
        profit   = target_pts * 4,      // Full target on runner
        loss     = 0,                    // BE stop (0 loss from entry)
        trail_points = 20 * 4,          // Trail by 20pts once at BE
        comment  = "RUNNER_TP")

Scale-Out Mechanics

Partial exit at 40pts: 50% of position closed  Runner to 80pts: trail stop 20pts  R:R on full trade: ~2:1

Scaling out at 50% of target and moving to breakeven means the worst-case outcome on any trade that reaches the first target is +40pts locked. This directly protects the EOD trailing drawdown floor from ratcheting up on an unrealized runner that reverses before the full target.

Auto-Flatten: 3:55pm ET Failsafe

GCP Cloud Task — Scheduled Close-All

A Cloud Scheduler job fires at 3:55pm ET daily and calls the Tradovate REST API to flatten all MNQ positions. No exceptions. This is the last line of defence against holding into 4:59pm and having the EOD drawdown snapshot a bad unrealized position.

Why 3:55pm and not 4:59pm

The Apex 4:59pm position close rule has a hard cutoff. A GCP task at 3:55pm gives a 4-minute buffer for any order latency, partial fills, or Tradovate API delays. Never rely on the exchange to close for you — the automated flatten is mandatory infrastructure.

Eval Protection Rules

RULE 1 GCP daily loss limit: $500 max. Hit it → GCP blocks all orders for the session.

RULE 2 No trades outside 7:55–8:30am ET. No exceptions. GCP time gate enforces this independently of Pine Script.

RULE 3 Max 2 trades per day. Second trade only if T1 stopped out cleanly and a new distinct sweep forms.

RULE 5 Scale-out at 50% target mandatory. Move stop to BE immediately. Never hold a full position to TP.
